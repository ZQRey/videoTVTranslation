# 💻 Desktop Multi-Screen Broadcast Player (`client/`)

Клиентское десктопное приложение для синхронного полноэкранного воспроизведения живой видеотрансляции RTSP на всех подключенных физических дисплеях, мониторах и телевизорах.

Построено на базе связки **PyQt6** (управление окнами, мультимониторный контроллер, фильтрация горячих клавиш) и нативного мультимедийного движка **libVLC** (аппаратное декодирование RTSP с минимальной задержкой).

## 🚀 Ключевые возможности и архитектура

- **Мультимониторность "из коробки"**: Приложение автоматически находит все подключенные к ПК мониторы и телевизоры (`QGuiApplication.screens()`) и разворачивает на каждом экране отдельное безрамочное полноэкранное окно (`PlayerWindow`).
- **Синхронное видео без эха**: Видео выводится синхронно на всех экранах, но **звук воспроизводится строго на одном экране (Primary)**. Все второстепенные мониторы принудительно заглушаются (`audio_set_mute(True)`).
- **Динамический хотплаг экранов**: При подключении или отключении мониторов/кабелей HDMI на лету контроллер автоматически пересоздает окна и переназначает вывод звука.
- **WebSocket-телеметрия и удаленный контроль**: Клиент держит постоянную связь с сервером вещания (`/ws/client`), передавая информацию об ОС, хосте и мониторах, и принимает серверные команды удаленного включения/отключения звука.
- **Двуязычные горячие клавиши**: Обработка клавиш в русской и английской раскладках (`Q`/`й` — настройки, `E`/`у` — выход).
- **Zero-Dependency Core**: Конфигурация клиента (`config.py`) написана строго на стандартной библиотеке Python (без использования сторонних библиотек вроде `pydantic`).

## ⚙️ Системные требования

1. **Операционная система**: Windows 10/11 (x64), Linux (X11 / Wayland), macOS.
2. **Python**: версия **3.10** или выше (поддерживаются 3.11, 3.12, 3.14).
3. **VLC Media Player (64-bit)**: На системе обязательно должен быть установлен 64-битный плеер VLC, содержащий библиотеку `libvlc.dll` (Windows) или `libvlc.so` (Linux).

### Установка VLC Media Player:
- **Windows (x64)**:
  ```powershell
  winget install VideoLAN.VLC
  ```
  *Либо скачайте установщик 64-битной версии с официального сайта: [videolan.org](https://www.videolan.org/vlc/).*
  > ⚠️ **Важно**: Версия VLC (32-bit или 64-bit) обязана совпадать с разрядностью установленного Python (x64).
- **Linux (Debian/Ubuntu)**:
  ```bash
  sudo apt update && sudo apt install -y vlc libvlc-dev
  ```
- **macOS**:
  ```bash
  brew install --cask vlc
  ```

## 📦 Установка и настройка окружения

### 1. Переход в папку клиента и создание venv
```powershell
cd client
python -m venv .venv
```

### 2. Активация виртуального окружения
- **Windows (PowerShell)**:
  ```powershell
  .\.venv\Scripts\Activate.ps1
  ```
- **Windows (CMD)**:
  ```cmd
  .\.venv\Scripts\activate.bat
  ```
- **Linux / macOS**:
  ```bash
  source .venv/bin/activate
  ```

### 3. Установка зависимостей
```bash
pip install --upgrade pip
pip install -r requirements.txt
```
> В `requirements.txt` входят только библиотеки интерфейса и мультимедиа: `PyQt6` и `python-vlc`.

## 🔨 Компиляция в исполняемый файл (.EXE)

Для развертывания клиента на пользовательских ПК без необходимости устанавливать Python и зависимости можно собрать автономный исполняемый файл с помощью **PyInstaller**.

### Шаг 1. Установка PyInstaller
```bash
pip install pyinstaller
```

### Шаг 2. Сборка приложения (Standalone Directory)
Выполните команду сборки из папки `client/`:
```powershell
pyinstaller --noconfirm --onedir --windowed `
    --name "StreamClient" `
    --add-data "client_config.json;." `
    main.py
```

### Шаг 3. Включение библиотек VLC (Для полной автономности)
Если целевой компьютер не имеет установленного VLC, скопируйте в собранную папку `dist/StreamClient/`:
- `libvlc.dll`
- `libvlccore.dll`
- папку `plugins/` (со всеми аудио- и видеокодеками VLC из `C:\Program Files\VideoLAN\VLC`).

После этого папка `dist/StreamClient/` может быть скопирована на любой компьютер с Windows и запущена файлом `StreamClient.exe`.

### Шаг 4. Настройка автозапуска при включении ПК (Windows)
Чтобы плеер запускался автоматически при старте Windows:
1. Нажмите `Win + R`, введите `shell:startup` и нажмите Enter.
2. Создайте ярлык для `StreamClient.exe` (или скрипта запуска `python main.py`) в открывшейся папке автозагрузки.

## 🚀 Запуск и параметры командной строки

### Стандартный запуск:
```powershell
cd client
python main.py
```

### Дополнительные флаги запуска:
```powershell
python main.py --host 192.168.1.100 --port 8554 --path /live --debug
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--config PATH` | `client_config.json` | Путь к альтернативному JSON-файлу конфигурации |
| `--host HOST` | `127.0.0.1` | IP-адрес или домен медиасервера |
| `--port PORT` | `8554` | RTSP порт потока вещания |
| `--path PATH` | `/live` | Путь RTSP потока |
| `--client-id ID` | Автоматически | Уникальный строковый идентификатор устройства |
| `--debug` | Выключен | Подробный вывод диагностических логов в консоль |

## ⚙️ Конфигурация (`client_config.json`)

При первом запуске приложение создает конфигурационный файл `client_config.json`:

```json
{
  "host": "127.0.0.1",
  "port": 8554,
  "stream_path": "/live",
  "client_id": "pc-2276wm-workstation",
  "fullscreen": true,
  "volume": 100,
  "ws_port": 8000
}
```

- Все параметры можно динамически редактировать через графическое окно настроек (клавиша **`Q`**).

## 🎮 Горячие клавиши и управление

| Клавиша (ENG) | Клавиша (РУС) | Действие |
|---|---|---|
| **`Q`** | **`Й`** | Открыть диалоговое окно настроек сервера (ввод IP-адреса, порта и пути). При открытии настроек звук временно глушится. |
| **`E`** | **`У`** | Корректное закрытие приложения с освобождением ресурсов libVLC и закрытием окон. |
| **`Esc`** | **`Esc`** | Закрыть диалог настроек и возобновить воспроизведение. |

## ⚠️ Критические инженерные особенности

1. **Запрет `pause()` на живом RTSP-потоке**:
   - Вызов нативного метода `_vlc_player.pause()` на RTSP-сокете Live555 приводит к полной блокировке (Deadlock) GUI Qt при последующем `play()`/`stop()`.
   - Для временного "скрытия" или "паузы" используется заглушение звука (`audio_set_mute(True)`), а видео продолжает циклично декодироваться в фоне.
2. **Отказоустойчивость сети**:
   - При кратковременной потере связи с сервером libVLC пытается переподключиться автоматически. Плеер не вылетает с ошибкой.
3. **Строгая изоляция звука**:
   - Звук включается **только** на Primary-экране и только тогда, когда с сервера получено разрешение `audio_allowed == true`.

## 🧪 Запуск тестов

В модуле клиента реализовано **15 автоматических тестов** (тесты ConfigManager, ClientConfig, хотплага мониторов, маршрутизации звука, WebSocket-уведомлений).

Тесты поддерживают запуск в headless-режиме (без физического монитора):
```powershell
cd client
python -m unittest discover tests
```

Ожидаемый результат:
```text
Ran 15 tests in 0.2s
OK
```
